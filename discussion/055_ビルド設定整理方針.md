# 055: ビルド設定整理方針

## 背景

ビルド関連の MSBuild 設定について、repo 全体共通設定と CLI 専用設定の配置自体は進んでいる一方、CLI versioning 設計では `EnableShortGitInformationalVersion` を残したままになっており、現在の運用意図とのずれがある。

現状調査では、以下を確認済みとする。

- `Directory.Build.props` で `Nullable` / `ImplicitUsings` / `TreatWarningsAsErrors` は既に repo 全体共通化されている
- `Version` と short SHA 付き `InformationalVersion` 付与ルールは `src/Adact.Cli/Adact.Cli.csproj` と `src/Adact.Cli.Client/Adact.Cli.Client.csproj` にのみ関係する
- `Adact.Cli` / `Adact.Cli.Client` は既に `build/Adact.Cli.Versioning.props` を import している
- `Directory.Build.targets` には `InformationalVersion` を short SHA 付きに補正する処理が存在する

今回の目的は、**既存配置を前提に責務定義を更新し、`EnableShortGitInformationalVersion` 廃止後の CLI versioning 方針を文書化すること** である。

---

## 決定事項

### 1. repo 全体で共通化する設定

- `Nullable`
- `ImplicitUsings`
- `TreatWarningsAsErrors`

これらは特定プロジェクト固有ではなく、repo 全体のコード品質・記述前提に関わるため、全プロジェクト共通設定として扱う。

`TreatWarningsAsErrors` は `true` を採用する。

### 2. CLI 専用共通設定としてまとめる設定

- `Version`
- short SHA 付き `InformationalVersion` 付与ルール

これらは `Adact.Cli` / `Adact.Cli.Client` で意味を持つ設定であり、repo 全体共通設定にはしない。

CLI 関連 project でのみ共有する前提で、**CLI 専用共通設定として 1 箇所に集約する**。

また、`EnableShortGitInformationalVersion` は false にしたい状況がなく、切替フラグとして保持する意味が薄いため、**フラグ自体を廃止し、CLI 2 project では short SHA 付き `InformationalVersion` を常設ルールとして扱う**。

### 3. CLI 専用共通設定の配置場所

CLI 専用共通設定はトップ直下に置かず、`build/` 配下に置く。

これにより、repo 全体共通設定と、特定プロジェクト群のための補助設定を物理的に分離する。

---

## 対象範囲

本方針を後続実装へ反映する際の対象は以下とする。

- 既存の repo 全体共通設定と CLI 専用設定の責務再定義
- `Directory.Build.props` / `Directory.Build.targets` と CLI 関連 project の責務整理
- `EnableShortGitInformationalVersion` 廃止後の CLI versioning 方針明文化
- Git なし環境における `InformationalVersion` 挙動の明文化
- `ContinuousIntegrationBuild` / `Deterministic` の説明上の扱い整理

---

## 非対象範囲

- 今回文書化した方針を超える追加のビルド最適化
- `Version` の値そのものの変更
- package / release フロー全体の再設計
- `ContinuousIntegrationBuild` / `Deterministic` の即時導入
- 過去の `discussion/` 文書更新

今回は設定整理方針の合意を残すことが目的であり、導入対象外の設定まで同時に広げない。

---

## 設定配置方針

### repo 全体共通設定

repo 全体で共通化する `Nullable`、`ImplicitUsings`、`TreatWarningsAsErrors` は、全 project に自然に適用される共通設定ファイルへ置く。

意図は以下のとおり。

- 各 `csproj` へ repo 共通の品質前提を持ち込まない
- 新規 project 追加時も同じ前提を自動適用する
- 「repo としての品質基準」を 1 箇所で読めるようにする

### CLI 専用共通設定

`Version` と short SHA 付き `InformationalVersion` 付与ルールは、CLI 系 2 project にだけ適用される共通設定として扱う。

配置方針は以下とする。

- repo 全体共通設定とは分離する
- トップ直下ではなく `build/` 配下に置く
- `Adact.Cli` / `Adact.Cli.Client` のみが参照する構成にする

この分離により、Windows 専用 CLI と cross-platform client に共通する配布・バージョニング都合をまとめつつ、他 project へ不要な意味を持ち込まない。

### `Directory.Build.targets` と CLI 専用 props の関係

short SHA 付与処理の**本体は `Directory.Build.targets` に残す**。

責務分離は以下とする。

- `Directory.Build.targets`: short SHA を使った `InformationalVersion` 補正処理の本体を持つ
- `build/Adact.Cli.Versioning.props` などの CLI 専用 props / import: 内部マーカー `_AdactCliVersioningEnabled=true` を設定し、その処理を適用すべき対象を `Adact.Cli` / `Adact.Cli.Client` に限定する

そのため、targets 側の処理は repo 共通の場所に存在してよいが、**適用対象の限定は CLI 専用 props / import 側で担保する**。ここで不要とするのは `EnableShortGitInformationalVersion` のような外部向け切替フラグであり、実装上は CLI 専用 props が内部マーカー `_AdactCliVersioningEnabled` を設定して opt-in する設計を採用する。

---

## Git がない環境の期待挙動

CLI 2 project で short SHA 付き `InformationalVersion` を常設ルールにした場合でも、Git が利用できない環境ではビルド失敗を必須挙動にしない。

期待挙動は以下とする。

1. まず `SourceRevisionId` が利用可能なら、その先頭 7 桁を `InformationalVersion` に付与する
2. `SourceRevisionId` が空の場合は `git rev-parse --short=7 HEAD` を試行する
3. Git 実行に失敗してもビルドは継続する
4. short SHA を取得できなかった場合、`InformationalVersion` は `Version` のままとする

つまり、Git なし環境での期待結果は **「short SHA なしでビルド成功し、`InformationalVersion` は `Version` にフォールバックする」** である。

---

## `ContinuousIntegrationBuild` / `Deterministic` の扱い

`ContinuousIntegrationBuild` と `Deterministic` は、今回の説明対象には含めるが、導入必須事項にはしない。

整理方針は以下とする。

- これらは再現性や CI 向けの性質に関わる設定候補として認識する
- 今回の主題はあくまで「既存設定の責務整理」であり、同時導入はスコープを広げるため必須化しない
- 後続で必要性が高まった時点で、別判断または追加合意として扱う

したがって、本件では **説明は残すが、設定追加の完了条件には含めない**。

---

## 想定される実装イメージ

- `Directory.Build.props` にある repo 全体共通設定は現状維持とし、本件では責務説明を更新する
- `build/Adact.Cli.Versioning.props` を基点に、CLI 2 project へ `Version` と short SHA 付与ルールを集約する
- `EnableShortGitInformationalVersion` は廃止し、CLI 専用 props を import する project では short SHA 付与を常時有効とする
- short SHA 付与処理の本体は `Directory.Build.targets` に残し、適用対象は CLI 専用 props / import で限定する
- short SHA 取得処理は、Git 取得失敗時でも `InformationalVersion=$(Version)` のまま成立する前提を維持する

既存ファイル配置を前提に、責務分離の原則はこの文書を基準とする。

---

## 次アクション

1. `build/Adact.Cli.Versioning.props` を起点とした CLI versioning 設計から `EnableShortGitInformationalVersion` を除去する
2. `Directory.Build.targets` 側の条件を、フラグ依存ではなく CLI 専用 props / import による適用対象限定へ整理する
3. `Adact.Cli` / `Adact.Cli.Client` で short SHA 付き `InformationalVersion` を常設ルールとして扱う実装にそろえる
4. Git なし環境で short SHA 取得失敗時もビルド継続し、`InformationalVersion` が `Version` にフォールバックすることを実装・確認する
5. `ContinuousIntegrationBuild` / `Deterministic` は別タスク化するか、必要性を追加判断する
