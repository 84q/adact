# 042 — CLI 出力形式統一設計

## 1. 背景と目的

ADACT CLI は、サブコマンドごとに JSON、プレーンテキスト、snapshot 本文直出しなど出力形式が揺れており、人間が連続して扱う際の見通しが悪い。

今回の設計では、**人間の見やすさを優先**して CLI 出力形式を統一する。既存出力との互換性は考慮せず、`--json` も導入しない。あわせて、成功時・失敗時の表現、snapshot の扱い、`sessionId` / `windowRef` の出し方を整理し、今後のサブコマンド追加時も迷わない基準を定める。

## 2. 設計方針

- 出力形式は **yaml風 / TSV風 / snapshot** の 3 パターンに統一する
- 全コマンドで、**先頭にメタ情報**、その後にセパレータ `---`、その後に**実行結果本体**を置く
- 出力先は **すべて stdout** に統一し、stderr は原則使わない
- 成功時は必ず `result: true` を出す
- 失敗時は必ず `result: false` と `error: <ERROR_CODE>` をメタ情報に出す
- 失敗時の本文は yaml風で `message` / `hint` 等を表現する
- `windowRef` は通常出力から廃止する
- `sessionId` はメタ情報から廃止し、必要なコマンドだけ本文側へ移す
- `unchanged` は独立キーを廃止し、snapshot パス末尾注記 `(changed)` / `(unchanged)` で表現する
- 出力なしコマンドはなくし、すべてのコマンドが何らかの結果を stdout に返す

> 補足: `serve http` / `serve pipe` は、要求ごとの結果を返して終了する通常サブコマンドではなく、サーバプロセスとして継続実行する系統である。そのため、本書の「各サブコマンド実行結果を標準化する出力フォーマット」の主対象外とする。

## 3. 共通出力ルール

### 3.1 基本構造

全コマンドの出力構造は次の 2 段構成とする。

1. メタ情報
2. `---`
3. 実行結果本体

```text
result: true
<必要に応じた追加メタ情報>
---
<実行結果本体>
```

### 3.2 メタ情報の役割

メタ情報は、本文を読む前に分かるべき共通情報を置く領域とする。最低限、以下を守る。

- 成功時: `result: true`
- 失敗時: `result: false`、`error: <ERROR_CODE>`
- `snapshot`、auto-snapshot 対象コマンドの成功時、および `attach` 成功時は、snapshot 本文そのものではなく **snapshot ファイルパス**をメタ情報に出す
- `sessionId` はメタ情報に出さない

### 3.3 `--no-snapshot` 時の成功出力

`attach` および auto-snapshot 対象コマンドで `--no-snapshot` を指定した成功時は、**snapshot 項目を単純に省略**する。

- `result: true` は必須
- `---` は必須
- 本文には通常どおりコマンド固有の結果を出す
- `snapshotPath` をダミー値や `null` で埋めない

### 3.4 本文の役割

本文には、そのコマンド固有の実行結果を置く。

- yaml風コマンド: キー/値ベースの結果
- TSV風コマンド: 表形式の結果
- snapshot コマンド: snapshot 本文

### 3.5 stdout / stderr

- 標準的な成功・失敗情報は **すべて stdout** に出す
- stderr は原則未使用とする
- これにより、利用者は stdout だけ見れば結果全体を把握できる

## 4. 形式別ルール（yaml風 / TSV風 / snapshot / error）

### 4.1 yaml風

最も基本となる形式。以下のコマンド群に適用する。

- 現状 JSON を返しているコマンド
- 操作結果を 1 件返すコマンド
- auto-snapshot 対象の操作コマンド

auto-snapshot 対象は、合意済みの次のコマンドに限る。

- ref 操作系: `click`, `fill`, `dblclick`, `hover`, `type`, `check`, `uncheck`, `select`, `clear`
- window 状態変更系: `resize`, `minimize`, `maximize`, `restore`

ルール:

- メタ情報は yaml風の単純なキー/値とする
- 本文も yaml風とする
- `attach` は yaml風とし、snapshot 本文ではなく snapshot ファイルパスをメタ情報に出す
- auto-snapshot 対象コマンドは yaml風とし、snapshot 本文ではなく snapshot ファイルパスをメタ情報に出す
- `sessionId` を本文に出すコマンドでは、本文先頭付近に置く

### 4.2 TSV風

TSV風は **`list-apps` / `close-all` のみ**に適用する。

ルール:

- メタ情報の後に `---` を置く
- 本文はタブ区切りの表形式とする
- `list-apps` の本文列では `windowRef` / `sessionId` を残す
- `close-all` は 1 件でも失敗があれば `result: false` とする
- `close-all` は部分失敗時でも本文を TSV のまま維持し、各 session の結果を行単位で出す
- それ以外の失敗時は TSV ではなく yaml風エラー出力に統一する

### 4.3 snapshot

snapshot 形式は **`snapshot` のみ**に適用する。

ルール:

- 共通メタ情報の後に `---` を置く
- snapshot パスはメタ情報側に置く
- その後に snapshot 本文をそのまま出す
- snapshot 本文の中では、**前置き情報**と**ツリー本文**を空行で区切る
- `snapshot` だけは、本文側の前置き情報に `sessionId` を出す
- `unchanged` は独立キーにせず、snapshot パス末尾の `(changed)` / `(unchanged)` で示す

### 4.4 error

失敗時は、原則としてコマンドの通常形式に関係なく、共通の yaml風エラー形式に統一する。

```text
result: false
error: <ERROR_CODE>
---
message: <人間向け説明>
hint: <必要なら復旧ヒント>
```

ルール:

- `list-apps` の失敗時は yaml風
- `close-all` だけは例外で、1 件でも失敗があれば `result: false` としつつ、本文は TSV のまま各 session 結果を出す
- `snapshot` も失敗時は yaml風
- 本文には少なくとも `message` を含め、必要に応じて `hint` や補足項目を追加する

## 5. サブコマンド別の最終出力分類表

### 5.1 分類ルール要約

- **TSV風**: `list-apps`, `close-all`
- **snapshot**: `snapshot`
- **yaml風**: 上記以外の 1-shot コマンド
- **対象外**: `serve http`, `serve pipe`

### 5.2 コマンド別一覧

| コマンド | 形式 | 補足 |
| --- | --- | --- |
| `list-apps` | TSV風 | 本文列として `windowRef` / `sessionId` を残す |
| `attach` | yaml風 | `result: true` + メタ情報に snapshot ファイルパス。`sessionId` は本文 |
| `snapshot` | snapshot | snapshot パスはメタ情報。`sessionId` は本文前置き情報。snapshot 本文内で前置き情報とツリー本文を空行区切り |
| `click` | yaml風 | auto-snapshot 時はメタ情報に snapshot ファイルパス |
| `fill` | yaml風 | auto-snapshot 時はメタ情報に snapshot ファイルパス |
| `dblclick` | yaml風 | auto-snapshot 時はメタ情報に snapshot ファイルパス |
| `hover` | yaml風 | auto-snapshot 時はメタ情報に snapshot ファイルパス |
| `mouse-move` | yaml風 | 低レベル操作。auto-snapshot なし |
| `mouse-down` | yaml風 | 低レベル操作。auto-snapshot なし |
| `mouse-up` | yaml風 | 低レベル操作。auto-snapshot なし |
| `mouse-wheel` | yaml風 | 低レベル操作。auto-snapshot なし |
| `press` | yaml風 | 低レベル操作。auto-snapshot なし |
| `key-down` | yaml風 | 低レベル操作。auto-snapshot なし |
| `key-up` | yaml風 | 低レベル操作。auto-snapshot なし |
| `type` | yaml風 | auto-snapshot 時はメタ情報に snapshot ファイルパス |
| `check` | yaml風 | auto-snapshot 時はメタ情報に snapshot ファイルパス |
| `uncheck` | yaml風 | auto-snapshot 時はメタ情報に snapshot ファイルパス |
| `select` | yaml風 | auto-snapshot 時はメタ情報に snapshot ファイルパス |
| `focus` | yaml風 | 補助操作。auto-snapshot なし |
| `clear` | yaml風 | auto-snapshot 時はメタ情報に snapshot ファイルパス |
| `scroll-into-view` | yaml風 | 補助操作。auto-snapshot なし |
| `resize` | yaml風 | auto-snapshot 時はメタ情報に snapshot ファイルパス |
| `minimize` | yaml風 | auto-snapshot 時はメタ情報に snapshot ファイルパス |
| `maximize` | yaml風 | auto-snapshot 時はメタ情報に snapshot ファイルパス |
| `restore` | yaml風 | auto-snapshot 時はメタ情報に snapshot ファイルパス |
| `inspect` | yaml風 | 現状 JSON 出力でも yaml風へ統一 |
| `screenshot` | yaml風 | `sessionId` は本文 |
| `wait-for` | yaml風 | `sessionId` は本文 |
| `wait-for-window` | yaml風 | エラー時も共通 yaml風 |
| `detach` | yaml風 | `sessionId` は本文 |
| `close` | yaml風 | `sessionId` は本文 |
| `kill` | yaml風 | `sessionId` は本文 |
| `close-all` | TSV風 | 1 件でも失敗があれば `result: false`。本文は TSV のまま各 session 結果を出す |
| `daemon-stop` | yaml風 | 出力なしにはしない |
| `install` | yaml風 | 出力なしにはしない |
| `launch` | yaml風 | 現状 JSON 出力でも yaml風へ統一 |
| `serve http` | 対象外 | サーバとして継続実行するため、本書の統一対象外 |
| `serve pipe` | 対象外 | サーバとして継続実行するため、本書の統一対象外 |

## 6. 代表例サンプル

### 6.1 yaml風成功例（`attach`）

```text
result: true
snapshotPath: .adact/snapshots/s1/0001.txt (changed)
---
sessionId: s1
processId: 12345
title: Untitled - Notepad
```

### 6.2 yaml風成功例（auto-snapshot 対象操作）

```text
result: true
snapshotPath: .adact/snapshots/s1/0008.txt (unchanged)
---
```

### 6.3 yaml風成功例（`attach --no-snapshot`）

```text
result: true
---
sessionId: s1
processId: 12345
title: Untitled - Notepad
```

### 6.4 TSV風成功例（`list-apps`）

```text
result: true
---
windowRef	sessionId	pid	title
w1	s1	12345	Untitled - Notepad
w2		67890	Calculator
```

### 6.5 TSV風結果例（`close-all` の部分失敗）

```text
result: false
---
sessionId	result	error
s1	true	
s2	false	CLOSE_FAILED
```

### 6.6 snapshot 成功例（`snapshot`）

```text
result: true
snapshotPath: .adact/snapshots/s1/0012.txt (changed)
---
sessionId: s1

- Window "Untitled - Notepad" [s1e1]
  - Edit [s1e2]: "hello"
```

### 6.7 失敗例（共通）

```text
result: false
error: NO_SUCH_SESSION
---
message: session 's99' was not found
hint: run 'adact list-apps' and attach again
```
