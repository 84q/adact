# Phase 6 要件定義 — Skill 機構 (`adact install --skills`)

## 1. 背景・動機

AI コーディングクライアントが ADACT を有効活用できていない。具体的な阻害要因:

1. AI クライアントは ADACT の存在やコマンド一覧を知らない。
2. コマンドを見つけても使い方・例がわからない。
3. エラー時の復帰パターン (特に `STALE_REF` など Phase 5 で導入された ref 安定化エラー) が伝わらない。
4. snapshot 出力が大きすぎてコンテキスト窓を圧迫する。**→ 本 Phase ではテクニックも触れない。Phase 7 (snapshot サイズチューニング) へ完全にパス。**
5. 「電卓を動かしたい」「メモ帳を動かしたい」等のボックスレシピがない。**→ Phase 6 のスコープ外 (将来 Phase で扱う)。**

`1` `2` `3` を解決することが Phase 6 の目的。

## 2. 解決方針

**Playwright Agent CLI (`@playwright/cli install --skills <agent>`) と同様のモデル**を採用する。
ADACT が `adact install --skills <client>` サブコマンドを提供し、各 AI クライアントが自動的に読み取るパスへ Skill ファイルを書き出す。

## 3. スコープ

### 3.1 対象サブコマンド (5 つ)

Skill として記述する ADACT サブコマンド:

- `attach`
- `snapshot`
- `click`
- `fill`
- `list_apps`

### 3.2 各 Skill に含める内容

- 使い方 (引数・基本フロー)
- 使用例
- エラー復帰パターン (`STALE_REF` 等を含む)

### 3.3 スコープ外 (Phase 6 では扱わない)

- 電卓・メモ帳などのボックスレシピ
- snapshot 出力の読み方ガイド・サイズ縮減テクニック (Phase 7 へパス)
- MCP ツールの `description` フィールド強化 (本 Phase では Skill ファイルでのみカバー)

## 4. 配布モデル

### 4.1 配布方法

`adact install --skills <client>` サブコマンドで、クライアント別の所定パスへ Skill ファイルをコピーする。

### 4.2 対応クライアント (3 つ同時サポート)

- VS Code GitHub Copilot
- Claude Desktop / Claude Code
- Codex (OpenAI)

各クライアントの自動読込パス・ファイル名規約は **設計フェーズで確定**する。

### 4.3 install スコープ

- 既定: リポジトリ単位 (cwd 配下に書き出す)
- `--global` オプション: ユーザーグローバル領域に書き出す

### 4.4 既存ファイル衝突時の挙動

- **上書き** (確認プロンプトなし)
- (`--force` 等のオプションは設計フェーズで検討)

### 4.5 Skill ファイルの記述言語

- **英語** (他ツール/エコシステムと揃える)

## 5. 完了判定基準

1. 3 クライアントすべてで以下を**手動スモーク**で確認する:
   - `adact install --skills <client>` が成功する
   - インストール後、各クライアントが ADACT を認識する
   - 与えたタスクを 5 サブコマンドの組み合わせで達成できる
2. 各 Skill ファイルの内容を**人間がレビュー**する。

(install コマンド自体の自動テスト整備は本 Phase の必須要件ではないが、設計フェーズで要否を判断する)

## 6. 設計フェーズへの引き継ぎ事項

以下は本要件定義では確定していない。設計フェーズで決定する:

- 各クライアントの自動読込パス・ファイル名規約 (リポジトリ / グローバル両方)
- Skill ファイルの粒度 (サブコマンドごとに 1 ファイル / 統合 1 ファイル / クライアントの慣例に従う)
- Skill ファイルの内部構造・テンプレート
- `install` コマンドの引数仕様 (`--skills <client>` の値、複数指定可否、`--global` 同時指定可否、`--dry-run` の要否 等)
- ADACT バイナリ内に Skill 原本を埋め込む手法 (埋め込みリソース / プロジェクト内 markdown を staticwebassets で参照 等)
- Skill 内容の保守フロー (ADACT 更新時に Skill をどう同期するか)
- install コマンド自体のテスト戦略
