# 安定セレクタ候補（inspect 拡張）

## 背景・目的

AIエージェントがFlaUIテストを自動生成する際、要素の特定方法（セレクタ）の選択が安定性に直結する。
現在の inspect は要素のプロパティとパターン情報を返すが、**どのように要素を特定すべきか**の示唆がない。

本機能は、inspect 実行時に「安定したFlaUIセレクタ候補」を算出し、コード例として提示する。

## ユースケース

- AIエージェントが inspect 結果を見て、そのままテストコードに利用できるセレクタを取得する
- 安定性レベルにより、セレクタの信頼度を判断できる

## 出力仕様

### 配置

inspect 出力の末尾に `selector` セクションとして追加。

### 形式

```yaml
selector:
  stability: High
  code: cf.ByAutomationId("btnOK")
```

祖先経路が必要な場合:

```yaml
selector:
  stability: Medium
  code: window.FindFirstDescendant(cf.ByAutomationId("panel1")).FindFirstDescendant(cf.ByName("OK").And(cf.ByControlType(ControlType.Button)))
```

### 安定性レベル

| レベル | 意味 | 条件 |
|--------|------|------|
| High | 構造変更に強い | AutomationId単独、またはControlType+Nameがウィンドウ全体でユニーク |
| Medium | 局所的な構造変更に耐える | 祖先スコープ内でName/ControlType等で一意に特定可能 |
| Low | 構造変更で壊れやすい | Index依存（要素の追加・削除で位置が変わる） |

## アルゴリズム

Playwright のセレクタ生成戦略をFlaUI/UIAに翻訳したもの。

### 優先順位

1. **AutomationId がウィンドウ全体でユニーク**
   - 出力: `cf.ByAutomationId("id")`
   - 安定性: High

2. **ControlType + Name がウィンドウ全体でユニーク**
   - 出力: `cf.ByName("name").And(cf.ByControlType(ControlType.X))`
   - 安定性: High

3. **祖先にAutomationIdを持つ要素がある → 祖先スコープ内で絞り込み**
   - 3a. 祖先スコープ内で自身のAutomationIdがユニーク
     - 出力: `window.FindFirstDescendant(cf.ByAutomationId("ancestor")).FindFirstDescendant(cf.ByAutomationId("self"))`
     - 安定性: High
   - 3b. 祖先スコープ内でName + ControlTypeがユニーク
     - 出力: `window.FindFirstDescendant(cf.ByAutomationId("ancestor")).FindFirstDescendant(cf.ByName("name").And(cf.ByControlType(...)))`
     - 安定性: Medium
   - 3c. 祖先スコープ内でControlType + Index
     - 出力: `window.FindFirstDescendant(cf.ByAutomationId("ancestor")).FindAllDescendants(cf.ByControlType(...))[N]`
     - 安定性: Low

4. **どの祖先にもAutomationIdがない場合**
   - ウィンドウ直下から ControlType + Index
   - 安定性: Low

### 設計方針

- ユニーク性チェックは snapshot（RefRegistry の EnumerateCurrent）を走査して行う
- 最初にマッチした（最も安定性の高い）候補を1つだけ返す
- inspect は低頻度操作のため、全要素走査のコストは許容する

## Playwright との対応関係

| Playwright 概念 | FlaUI/UIA 相当 |
|-----------------|----------------|
| TestId (data-testid) | AutomationId |
| Role + Name | ControlType + Name |
| Parent filtering / chaining | 祖先の AutomationId からの経路 |
| nth() | Index（最終手段） |
| Strict mode (>1 match で例外) | ユニーク性チェック |

### 新規型

#### SelectorSuggestion

```
sealed record SelectorSuggestion(string Stability, string Code)
```

- `Stability`: "High" | "Medium" | "Low"
- `Code`: FlaUI コード例（1行チェーン）

#### AncestorInfo

```
sealed record AncestorInfo(string? AutomationId, string? Name, string ControlType)
```

祖先チェーンの各ノード情報。WindowSession.Inspect.cs で FlaUI `AutomationElement.Parent` を使って構築し、SelectorSuggester に渡す。

### SelectorSuggester

```
static class SelectorSuggester
{
    static SelectorSuggestion Suggest(
        IElement target,
        IEnumerable<IElement> allElements,
        IReadOnlyList<AncestorInfo> ancestors)
}
```

- FlaUI 非依存（IElement + AncestorInfo のみ）
- Unit テスト可能（FakeElement で構築可能）
- 入力の `ancestors` は対象要素の直接の親から順にルート方向へ並ぶ

### 祖先チェーン構築（WindowSession.Inspect.cs）

```
FlaUI AutomationElement.Parent を繰り返し呼び出し、
各ノードの AutomationId / Name / ControlType を AncestorInfo に変換。
ウィンドウルート（= セッションの対象ウィンドウ）に到達したら停止。
```

### ユニーク性チェック

- データソース: `RefRegistry.EnumerateCurrent()` が返す全 `IElement`
- 祖先スコープの判定: ancestors 中の AutomationId 付き要素を見つけたら、allElements から同じ AutomationId を持つ祖先の子孫を絞り込む
  - 実装: allElements 全体を走査し、対象の AutomationId に一致する要素の子孫ツリーを再帰的に展開して比較
  - 代替: RefRegistry に追加のスコープ絞り込みは入れず、allElements フラット走査 + 祖先スコープは「全要素中でその祖先の子孫にあたるもの」をフィルタ

### テストパターン

| # | シナリオ | 期待結果 |
|---|----------|----------|
| 1 | AutomationId がウィンドウ全体でユニーク | High, `cf.ByAutomationId("btnOK")` |
| 2 | AutomationId が重複 | 次の候補に進む |
| 3 | ControlType+Name がユニーク | High, `cf.ByName("OK").And(cf.ByControlType(ControlType.Button))` |
| 4 | ControlType+Name も重複 | 祖先パスに進む |
| 5 | 祖先スコープ内でAutomationIdユニーク | High, チェーン |
| 6 | 祖先スコープ内でName+ControlTypeユニーク | Medium, チェーン |
| 7 | 祖先にAutomationIdなし | Low, Index |
| 8 | AutomationId が null/空 | AutomationId候補スキップ |
| 9 | 要素が1つだけ | High（何でもユニーク） |
