# テスト改善計画

> 前提: [.agents/skills/testing-strategy/SKILL.md](../.agents/skills/testing-strategy/SKILL.md)
> 参照: [022_Phase8設計.md](022_Phase8設計.md) / [025_Phase8_完了.md](025_Phase8_完了.md)
> 目的: 現行の Unit / Integration テストとカバレッジ結果を踏まえ、今後改善すべきテスト領域と優先度を整理する。

---

## 1. 現状サマリ

Unit / Integration の現行カバレッジでは、L1 Unit は比較的厚い一方で、L2 Integration と主要フローの成功パスが不足している。

確認時点の主な状況:

- Trait 分布: `Unit 40`, `Integration 3`, `IntegrationUia 1`, `Smoke 5`, `E2E 3`
- 統合カバレッジ: line `43.5%`, branch `40.9%`
- `Adact.Cli` は snapshot parser / formatter / filter や config / ref validation は厚い
- `Adact.Engine` は `SnapshotBuilder` / `RefRegistry` は厚いが、`WindowSession` 操作系が薄い
- `Adact.Mcp.Common` は `WindowRefStore` は厚いが、`WindowsTools` の成功パスが薄い
- `Adact.Cli.Server` / `Adact.Mcp.Stdio` は Unit / Integration カバレッジ上ほぼ未到達

## 2. 改善方針

testing-strategy の 5 層を維持し、追加テストは以下の方針で分類する。

| Layer | 方針 |
| --- | --- |
| L1 Unit | pure logic、引数検証、エラー変換、出力整形、MCP response parsing を高速に検証する |
| L2 Integration | FakeElement / fake client / fake session を使い、CLI -> MCP、MCP -> Engine、snapshot text pipeline の成功フローを検証する |
| L3 IntegrationUia | 実 UIA tree 由来の最小代表ケースだけを置く |
| L4 Smoke | Calculator / Notepad++ など、実アプリに対する代表操作を少数に絞る |
| L5 E2E | transport ごとの疎通確認に限定し、詳細網羅は L1 / L2 に寄せる |

当面の改善対象は **L1 / L2** を中心とする。実アプリ依存を増やす前に、共通フローと委譲ロジックを fake で厚くする。

## 3. 優先度一覧

### P0: 最優先

| 対象 | 不足 | 追加したいテスト | Layer |
| --- | --- | --- | --- |
| `Adact.Cli.Commands.CommandHelpers` | line coverage が低く、CLI の共通成功フローが未検証 | `WriteSnapshotResultAsync` の正常系、unknown filter、snapshot error、missing sessionId、invalid JSON、raw / operable filter | Unit / Integration |
| `CommandHelpers.RunRefOperationAndAutoSnapshotAsync` | auto-snapshot 対象コマンドの中核分岐が薄い | operation error、`--no-snapshot`、ref から sessionId 抽出、snapshot 失敗伝播 | Unit / Integration |
| `CommandHelpers.RunSessionOperationAndAutoSnapshotAsync` | window state 系コマンドの共通分岐が薄い | operation error、明示 sessionId、active session、`--no-snapshot`、snapshot 失敗伝播 | Unit / Integration |
| CLI action commands | 不正引数テストに偏り、成功時の MCP tool 呼び出しが薄い | `click`, `fill`, `press`, `type`, `hover`, `mouse-*`, `resize` の tool name / args / output | Unit / Integration |

P0 は多くの CLI コマンドに波及するため、最初に着手する。ここを厚くすると、以後の個別コマンド追加時の回帰検知力が上がる。

### P1: 高優先

| 対象 | 不足 | 追加したいテスト | Layer |
| --- | --- | --- | --- |
| `Adact.Mcp.Common.WindowsTools` action 系 | invalid / no-active / unknown-session が中心で、成功委譲が薄い | fake session を使った `windows_click`, `windows_fill`, `windows_press`, `windows_type`, `windows_mouse_*`, toggle 系の成功委譲 | Unit / Integration |
| `WindowsTools` error mapping | Engine 例外から MCP error への変換の網羅が薄い | `RefNotFoundException`, `ElementInteractionException`, `WaitTimeoutException`, `WindowNotFoundException`, `LaunchFailedException` の変換 | Unit |
| `SessionStore` 周辺 | 複数 session / active session / detach 後の挙動が主要フローとして薄い | register、active 切替、remove、resolve by ref、dispose の組み合わせ | Unit |
| `WindowRefStore` と `ListApps` / `Attach` の結合 | store 単体は厚いが、MCP tool 経由の同期が薄い | list -> retired -> attach、既存 session 再利用、retired ref error | Integration |

P1 は MCP の実利用 API の信頼性に直結する。UIA 実体を呼ばずに fake で検証できる形を優先する。

### P2: 中優先

| 対象 | 不足 | 追加したいテスト | Layer |
| --- | --- | --- | --- |
| `Adact.Engine.WindowSession` 操作系 | line coverage が低く、ref 解決後の操作委譲が薄い | `ClickAsync`, `FillAsync`, `PressAsync`, `TypeAsync`, `MouseMoveAsync`, `Toggle` 系の正常委譲と例外変換 | Integration |
| `WindowSession.Wait` | 状態判定と timeout / cancel の組み合わせが薄い | visible / hidden / enabled / disabled / detached、query match、timeout、cancellation | Unit / Integration |
| `FlaUiElement` 境界 | 実 UIA wrapper の多くが L1/L2 では未到達 | 直接網羅は追わず、L3/L4 の代表ケースで実 UIA property が snapshot に反映されることを確認 | IntegrationUia / Smoke |
| `InteractiveSessionGuard` / `NativeMethods` | OS 依存が強く、Unit ではノイズが大きい | pure 判定部分のみ Unit、OS 依存は smoke で代表確認 | Unit / Smoke |

P2 は Engine 内部の品質を上げる領域。fake 化しやすい箇所から進め、OS 依存の細部は過剰に Unit 化しない。

### P3: 後続

| 対象 | 不足 | 追加したいテスト | Layer |
| --- | --- | --- | --- |
| `Adact.Cli.Server` | Unit / Integration カバレッジ上 0% | `HttpHost` の route / DI 構成、`HttpDaemonControl` の stop 呼び出し | Smoke / E2E |
| `Adact.Mcp.Stdio` | Unit / Integration カバレッジ上 0% | stdio host 構成、daemon control、transport 起動失敗時の扱い | E2E |
| `AdactMcpClient` | 接続成功 / 失敗、tool error の境界が薄い | fake server または loopback server による connect / call / disposal | Integration |
| カバレッジレポート運用 | Unit/Integration と Smoke/E2E が混ざると判断しづらい | Layer 別レポート、assembly 除外ルール、zero coverage assembly の扱いを整理 | Test infra |

P3 は実行コストや環境依存が上がるため、P0/P1 で pure / fake の土台を整えてから進める。

## 4. 推奨実施順

| Step | 内容 | 完了イメージ |
| --- | --- | --- |
| 1 | `CommandHelpers` を fake client でテストしやすくする | auto-snapshot の中核分岐が Unit / Integration で検証されている |
| 2 | CLI action command の成功フローを追加 | 主要 CLI コマンドが正しい MCP tool name / args を送ることを検証できている |
| 3 | `WindowsTools` の fake session 成功委譲を追加 | MCP tool が正しい `WindowSession` メソッドへ委譲することを検証できている |
| 4 | `WindowSession.Wait` と操作系の L2 を追加 | ref / query / state / timeout の重要分岐が fake element で検証されている |
| 5 | Layer 別カバレッジレポートを整理 | Unit/Integration の改善量と Smoke/E2E の未到達領域を分けて読める |
| 6 | Server / Stdio の代表 smoke / E2E を追加 | transport ごとの起動・疎通・停止が代表ケースで確認できている |
| 6 補助 | 代表 smoke / E2E の安定運用を整える | 外部 daemon 接続、Calculator 検出、非対話 session skip の運用が明確になっている |

## 5. 完了条件

短期の完了条件:

- P0 の対象が一通りテストされている
- Unit / Integration のカバレッジで `CommandHelpers` と CLI action commands の主要成功パスが見える
- auto-snapshot 対象コマンドの `--no-snapshot` / snapshot 成功 / snapshot 失敗が回帰検知できる
- 追加テストは `Trait("Layer", "...")` を持ち、testing-strategy の分類と一致している

中期の完了条件:

- P1 の `WindowsTools` 成功委譲が一通り揃っている
- `WindowSession` の pure / fake で検証できる操作系が L2 に寄っている
- Unit / Integration と Smoke / E2E のカバレッジレポートが分離され、0% assembly の意味が明確になっている

---

## 6. 注意点

- coverage 数値だけを目標にしない。優先するのは、共通フロー、エラー変換、ユーザー-visible な出力、層間 contract の回帰検知。
- 実 UIA / 実アプリ起動を伴うテストは L3 以上に置き、L1 / L2 へ混ぜない。
- `WindowSession` や `WindowsTools` のテスト容易性を上げるために抽象化を追加する場合は、既存構造に沿って最小限にする。
- Smoke / E2E の詳細網羅は避ける。transport と代表フローの確認に留め、分岐網羅は Unit / Integration に寄せる。
